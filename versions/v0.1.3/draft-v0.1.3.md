### Timeline as a real dated schedule, with reordering
- Type: Amendment
- Amends: F-006
- Description: From the review of v0.1.2: the timeline is currently an abstract proportional bar — it shows the ratio of phases' work-days but no real schedule. Make it a real dated timeline using the start date and per-phase working-days already captured, and let phases be reordered.
- New text: While creating or editing a project, phases are added as blocks chosen from "Project phases"'s known list (or a custom one), and can be reordered (moved up or down); the timeline recalculates live whenever a phase is added, edited, reordered, or removed. Each phase optionally takes a planned number of work days. When a start date is set, every phase gets a real calendar date range: the first phase runs from the start date for its work-days (skipping weekends), and each next phase picks up where the previous one ends; a hold's duration, once set (see "Put a project on hold, with a reason and duration"), extends this the same way a phase's work-days do, at the point it applies. The phase list shows each phase's computed date range next to it as the plan is built. The timeline itself lays these out Gantt-style — one row per phase (and the hold, where it applies), positioned and sized by its real dates — instead of a single proportional bar. Without a start date, the timeline falls back to relative work-day proportions with no dates. The calculated end date (start date plus every phase's and any hold's work-days) is always shown; if the project manager also chose an end date, both show side by side, and the calculation never overwrites the chosen one. This is the planned schedule only — actual progress against it stays out of scope until "Phase progress reporting" exists.
- Done when: Once a start date is set, each phase shows its own real date range in the phase list and as a positioned row on the timeline (Gantt-style, including the hold's row where it applies); phases can be reordered with every date updating live; the calculated end date still reflects the full plan.
- Also serves: none

### Mark a project as launched — amendment
- Type: Amendment
- Amends: F-009
- Description: From the review: the separate checklist duplicated the phase list and launching happened without any confirmation. Fold completion-marking into the existing phase list (one row, one place — see "Timeline / phase builder"), and require the project manager to confirm before the project actually launches.
- New text: Marking a project launched is not a bare on/off switch. Each phase in the project's phase list (see "Project phases" / "Timeline / phase builder") gets its own "complete" checkbox on its own row — there is no separate checklist. Once every phase is marked complete, "Mark as launched" becomes available. Clicking it asks for confirmation first, with a small on-page prompt ("Do you confirm?"), and only launches once confirmed. This is self-declared — it is not verified against real progress data, because there is no phase-progress-reporting feature yet (see "Phase progress reporting" in the backlog, currently Later). Once that exists, phase completion could be upgraded to check real progress instead of taking the project manager's word for it.
- Done when: Each phase can be marked complete inline, on its own row in the phase list; once every phase is marked complete, "Mark as launched" becomes available; clicking it shows an on-page confirmation prompt, and the project's status only becomes Launched once confirmed.
- Also serves: none
- Open questions: A phase added after some others are already marked complete — does it reset the others back to incomplete, or just add one more incomplete item? (Leaning toward: just adds one more item, nothing resets.)
